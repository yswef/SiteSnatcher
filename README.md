# SiteSnatcher — تحميل المواقع للعمل بدون إنترنت

تطبيق سطح مكتب بلغة بايثون بواجهة داكنة احترافية، يقوم بتحميل موقع كامل (صفحات + CSS + JS + صور + خطوط) وإعادة بناء نفس هيكل المجلدات محلياً، ثم إعادة كتابة كل الروابط لتعمل بالنقر المباشر بدون اتصال.

---

## 1. التشغيل

```bash
pip install -r requirements.txt
python main.py
```

> على لينكس قد تحتاج: `sudo apt install python3-tk`
> مكتبة `lxml` اختيارية (تسريع التحليل)، وإذا لم تُثبَّت يُستخدم `html.parser` تلقائياً.

---

## 2. هيكل المشروع

| الملف | الوظيفة |
|---|---|
| `main.py` | نقطة الدخول فقط |
| `core/url_utils.py` | تحويل الروابط إلى مسارات ملفات محلية + تحديد نطاق الموقع |
| `core/rewriter.py` | استخراج الروابط من HTML/CSS وإعادة كتابتها |
| `core/crawler.py` | محرك التحميل متعدد الخيوط (Threads) |
| `ui/app.py` | الواجهة الرسومية (CustomTkinter) |
| `ui/theme.py` | الألوان والأحجام ودوال التنسيق |
| `selftest.py` | اختبار ذاتي شامل بدون إنترنت |

---

## 3. المنطق الأساسي: لماذا مرحلتان؟

هذه أهم نقطة في التصميم، وهي سبب عمل الروابط بشكل صحيح:

**المرحلة الأولى — التحميل فقط:**
كل صفحة/ملف يُحمَّل ويُحفظ كما هو على القرص، مع بناء جدول `{الرابط الأصلي → المسار المحلي}`. لا يتم تعديل أي رابط في هذه المرحلة.

**المرحلة الثانية — إعادة الكتابة:**
بعد اكتمال الجدول، تُفتح كل ملفات HTML و CSS المحفوظة وتُستبدل روابطها بمسارات نسبية (`../assets/logo.png`).

**السبب:** أثناء التحميل، الرابط قد يشير إلى صفحة لم تُحمَّل بعد، أي أن اسمها المحلي النهائي غير معروف (يعتمد على نوع المحتوى `Content-Type`). إعادة الكتابة في النهاية تلغي هذه المشكلة كلياً بدل التخمين.

### قواعد تحويل المسارات (`local_path_for`)

| الرابط | الملف المحلي |
|---|---|
| `https://site.com/` | `site.com/index.html` |
| `https://site.com/a/b.html` | `site.com/a/b.html` |
| `https://site.com/a/b/` | `site.com/a/b/index.html` |
| `https://site.com/about` (HTML) | `site.com/about.html` |
| `https://site.com/p.php` (HTML) | `site.com/p_php.html` |
| `https://site.com/p?id=3` | `site.com/p_q8c1f0a2.html` |

- الامتداد يُحدَّد من `Content-Type` وليس من شكل الرابط.
- الاستعلام (`?query`) يُحوَّل إلى بصمة MD5 قصيرة حتى لا تتصادم الملفات.
- الأحرف الممنوعة في أسماء الملفات تُنظَّف، والأسماء الطويلة تُقصَّر مع بصمة لضمان عدم التكرار.
- يُنشأ ملف `index.html` في جذر مجلد الحفظ يفتح الصفحة الرئيسية مباشرة.

### ما الذي يُستخرج؟

`a[href]`, `link[href]`, `script[src]`, `img[src/srcset/data-src]`, `source`, `video[poster]`, `audio`, `iframe`, `object[data]`, `embed`, `body[background]`, وسمات `style=""` المضمّنة، ووسوم `<style>`، وداخل ملفات CSS: `url(...)` و `@import`.
يُحذف وسم `<base>` عند إعادة الكتابة لأنه يكسر المسارات النسبية في وضع عدم الاتصال.

## 4. المحرك (Crawler)

- عدد خيوط قابل للضبط (افتراضي 8) مع طابور مشترك آمن (`queue.Queue` + `Lock`).
- `max_depth`: عمق الروابط، و`max_pages`: سقف عدد الصفحات (الأصول لا تُحسب ضمنه).
- إيقاف/استئناف فوري عبر `threading.Event`.
- احترام `robots.txt` (قابل للإيقاف)، تأخير اختياري بين الطلبات، حد أقصى لحجم الملف.
- التعامل مع إعادة التوجيه (Redirect): يُسجَّل الرابطان (الأصلي والنهائي) على نفس الملف.
- الواجهة لا تتصل بالشبكة إطلاقاً؛ التواصل بين المحرك والواجهة يتم عبر طابور أحداث تقرأه حلقة `after()` كل 120ms، لذلك النافذة لا تتجمد أبداً.

## 5. الاختبار الذاتي (مهم)

بدل الاعتماد على التخمين، المشروع يحتوي على `selftest.py` الذي:
1. يشغّل موقعاً تجريبياً على `127.0.0.1` بمنفذ عشوائي.
2. ينسخه بالمحرك الحقيقي.
3. يفحص **كل** رابط محلي في الناتج ويتأكد من وجود الملف فعلياً على القرص.

```bash
python selftest.py
```

## 6. حدود معروفة (بدون تجميل)

- المحتوى المُولَّد عبر JavaScript (React/Vue/SPA) لا يُحمَّل، لأن المحرك لا يشغّل متصفحاً. الحل المستقبلي: إضافة خلفية `Playwright`.
- الملفات خلف تسجيل دخول تحتاج إضافة Cookies (غير مُفعَّلة حالياً).
- `srcset` يُعاد كتابته، لكن الصور المحمّلة عبر JS ديناميكياً لن تُلتقط.
- استخدم التطبيق فقط على مواقع تملكها أو مسموح لك بنسخها.
